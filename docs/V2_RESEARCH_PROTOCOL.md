# V2：可靠来源、真伪核验与严格样本外协议

V2 的目标不是提高历史样本的命中率，而是把“社区弱信号 -> 事实核验 -> A 股盈利暴露 -> 预期差 -> 可执行回测”变成可审计流程。

## 关键改变

论坛不再直接提供“真值”。论坛只负责发现可能的现实变化。事实判断必须区分原始出处、作者是否一手、具体程度、独立来源组、支持与反驳证据，并优先由公告、统计、招投标、海关、行业数据或具方法说明的专业数据源交叉核验。

V1 对“公司已经公开谈过这个主题”扣分过重。V2 不再把“已公开”本身视为负面；真正要判断的是新增信息的**幅度、持续性和盈利含义**是否超过当时市场预期，以及分析师/价格是否已经完成修正。

## 五段式证据链

1. **Discovery**：固定时间窗和固定操作型词表搜寻缺货、交期、订单、库存、涨价、产能、认证、交付等事实型线索，不用“牛股/翻倍/涨幅”等结果导向词。
2. **Verification**：检索反证；同一通讯稿、同一匿名消息源、同一转载链只算一个 independence group。社区帖可为 probable，但 confirmed 通常需要 primary/professional-data 支持。
3. **Economic mapping**：只按当时可公开获取的产品直接性、收入重要性、区域/客户匹配和可用产能评分。概念股归类不给高分。
4. **Expectation gap**：看需求变化幅度、持续时间、盈利敏感度和市场预期修正是否滞后；“公开过”不等于“定价完成”。
5. **Outcome unlock**：候选集合和不交易决策先提交 Git commit；之后才能抓取信号后的价格，并按 T+1、成本、涨跌停/停牌约束计算 20/60/120/250 交易日超额收益。

## 来源使用原则

- **primary_official**：交易所/公司公告、政府统计、海关、公开招投标、监管/行业协会原始数据。用于事实核验和经济暴露。
- **professional_data**：有署名来源或方法说明的行业媒体/追踪数据、业绩会记录。用于交叉核验和幅度估计。
- **practitioner_firsthand**：真正从事采购、安装、运维、制造、渠道工作的讨论。用于早期弱信号。
- **specialist_forum**：技术社区但作者身份/一手程度不清。只能作发现或低权重支持。
- **investor_social**：雪球、股吧等。更适合衡量市场注意力/叙事饱和，而不是单独证明事实。
- **repost**：聚合、洗稿、同源转载不给独立支持票。

## 真伪识别不做“LLM 一票判真”

程序输出的是 evidence status，不是“真相概率”。核心是可审计证据：原始 URL、发布时间、首次可得时间、作者/角色、一手性、可证伪细节、独立来源、反证、是否后来编辑、是否带有明显推票语言。

V2 会把同一 independence group 的重复报道封顶，只取其中最高质量的一条，防止“十家媒体转载同一消息”被误判为十个独立证据。

下一步按窗口顺序登记所有达到最低可核验标准的线索（包括反例和最后不交易的窗口），先提交 selection commit，再解锁后续价格。
