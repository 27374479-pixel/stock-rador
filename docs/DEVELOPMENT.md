# 社区线索最小实验

## 要回答的问题

论坛里一条有日期、可证伪的讨论，能否在市场充分定价前揭示 A 股公司的盈利预期差？第一阶段只做一件事：保存真实社区命题，记录当时究竟能知道什么，再用独立原始资料核验，最后判断它是否值得继续研究。

`S` 只表示“优先深挖”，不是买入信号、收益承诺或投资建议。CLI 校验的是录入字段和证据门槛；`verified` 仍是人工录入的判断，不代表程序自动鉴真。评级前必须打开原文核对内容、独立性和经济关系。

## 第一轮怎么做

1. 当前首轮试运行保存了 6 条真实记录，用于打通格式和门槛；下一轮固定时间窗的实验计划收集 10 至 20 条。命题应具体且可证伪，例如需求、价格、交期、产能、客户资本开支或产品认证发生变化。弱线索和反例也保留，看到后续涨跌再挑样本会让实验失真。
2. 分开保存帖子发布时间 `source.publishedAt`、首次观察时间 `observedAt`、最早可证明进入本数据集的时间 `availableAt` 和实际访问时间 `source.accessedAt`。不知道发布时间时写 `null` 并设置 `datePrecision: "unknown"`，不得编造时分。`truthStatus` 一旦不再是 `unknown`，同时记录形成该判断的 `truthAssessedAt`。
3. `availableAt` 不能倒填成帖子发布时间。今天搜索到一篇旧帖，通常只证明它今天仍可见；除非有网页存档、同期采集日志等证据，`availableAt` 应记今天。没有可靠发布时间的论坛 origin 可以保存为 Watch，但不能用于历史入场判断。核验证据即使不知道原始发布时间，只要今天确实打开并记录了 `availableAt`，仍可支持今天的事实判断；它只不能泄漏到 `availableAt` 之前的历史截点。
4. 保存访问范围：查过哪些平台、查询方式、登录或付费墙限制、删除内容、搜索/API 覆盖缺口。只看到摘要或局部正文时使用 `textAvailability: "snippet_only"` 或 `"partial"`，不能升为 A/S。
   同时记录 `contentKind`：`original_discussion`、`news_repost` 或 `unknown`。资讯号转载的帖子正文不是社区原创发现，应作为传播对照样本；但转载帖下的原创评论可能提出新的采购、订单或交期命题，不能因主帖是转载而一并丢弃。评论必须单独拆成 lead，`source.url` 精确定位到评论，独立记录作者、时间、正文可用性和可证伪命题，满足条件时才标为 `original_discussion`。现有 CLI 不会自动解析帖子和评论的层级，这一步需要人工完成。
5. 新命题的 `truthStatus` 先记 `unknown`。只有已有证据时才改成 `supported`、`contradicted` 或 `mixed`。尚未确认是未知，不是虚假。
6. 增加独立核验证据。同一通讯稿的多个转载、引用同一匿名消息的文章、重复公司同一份公告的报道应使用相同 `independenceGroup`，不能靠不同域名凑成多源。
7. 只有存在可审计的经济传导路径才映射 A 股。概念板块归类或产品名称重合只能写 `claimed`；分部收入、披露客户或订单、相关产能等原始材料才可能支持 `verified`。
8. 按日期写清估值或市场预期差。公司质地好但没有“当时市场预期是什么”的证据，不能进 S。
9. 升级前预先写至少一个可观察的失效指标。命题被否定或指标触发时进入 `Reject`，记录仍保留，防止只留下成功案例。

每周可在补充证据后复核一次。仓库现有一个公开 HN Algolia API 的固定窗口、有界采集脚本，可保存单次运行快照；它没有调度、持续监控或跨期热度序列能力，也不声称已经安排任何自动检查。

首轮有限实验应先固定一个社区集合和时间窗，对可获得样本全量登记，再锁定 claim、A 股映射和评级，最后才查看后续表现。若能取得点时价格，记录 T+1 开盘可成交性、涨停/停牌、复权、交易成本，并比较沪深 300 和行业基准的 20 日、60 日收益与回撤。若没有历史快照，只能做探索性样本回放；同时从本轮 `observedAt` 冻结前向样本，不能把结果称为 alpha 验证。

## 评级门槛

`Reject`：原始命题已被否定，或预先设置的失效指标已经触发。它不进入活跃候选，但必须留在样本中。

`Watch`：默认状态。包括早期、未知、原文不可完整核对、核验证据不足或 A 股经济暴露未验证的命题。

`A` 必须同时满足：

- 论坛原文完整可访问，来源与时间可追溯；
- 至少一项可检验的失效指标；
- 至少一项独立的 primary 原始来源支持；
- 至少一个 A 股映射具有经证据引用支持的 `verified` 经济暴露；
- 命题没有被否定。

`unknown` 或 `mixed` 可以保持 A，因为不确定性需要如实保留。

`S` 在 A 的基础上还必须满足：

- `truthStatus` 为 `supported`；
- 支持证据至少来自两个独立 origin group；
- 至少一个 A 股映射同时具备已验证的经济暴露，以及带日期、带证据引用的估值或预期差。

这些只是研究证据的必要条件。流动性、治理、会计质量、下行风险和交易价格不在这个最小实验内。
程序会排除与论坛 origin 同域名的“primary”证据，但无法自动判断不同域名是否实际来自同一稿源，也无法判断 `independenceGroup` 是否诚实命名；输出仍需人工原文核验。

## 数据约定

主文件为 `research/forum_leads.json`。顶层包含 `schemaVersion: "1.0"`、文件时间、明确的 `accessScope` 和 `leads`。发现过程还可以保存 `discoveryMethod`，包括查询词、筛选规则、候选或入选或拒绝数量和限制；`rejectedLeads` 保存拒绝原因，让检索分母可见。

每条 lead 包含：

- 稳定 `id`、`observedAt` 与 `availableAt`；
- forum `source`，含访问方式、状态、正文可用程度与时间精度；
- 可核验的 `claim` 和显式 `truthStatus`；
- `verificationEvidence`，含支持或反驳关系、来源类型、独立来源组和三类时间；
- `invalidationIndicators`，含观察方法和当前状态；
- `aShareMappings`，分开记录业务暴露与估值或预期证据；
- 可选的 CLI 评审结果 `assessment`。

`evidenceRefs` 必须指向同一 lead 内真实存在的 `verificationEvidence.id`。历史截点评审还要求被引用证据在截点前已经可获得。校验器只能确认结构和引用关系，无法确认网页正文是否真的支持录入结论。

## 历史复核的边界

如能取得真实帖子、可靠的同期时间和点时市场数据，第一轮只能称为“历史样本复核”（retrospective sample review）。报告必须包含全部入样线索、信息截点、评级随时间的变化以及正反结果。论坛搜索的幸存者偏差、删除或编辑内容、时间泄漏和小规模主观样本都可能主导结果，因此不能称为回测或 alpha 验证。

实验目标仍是验证是否存在可投资机会。当前样本尚未确认机会，含义是证据链未闭合；它既不能被包装为成功，也不能据此宣告社区研究策略失败。

使用以下命令按当时信息复核：

```powershell
node src/cli.js review research/forum_leads.json --as-of 2026-09-21T08:00:00.000Z
```

CLI 会排除 `availableAt` 晚于截点的证据，也不会让晚于截点的估值证据通过。真正的 alpha 验证还需要前瞻冻结的采集规则、对照集合、`availableAt` 之后可执行的成交价、交易成本、退市样本和足够多的观测量；当前仓库尚不具备这些条件。
